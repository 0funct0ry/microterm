# M10.1 — ctl: resource-oriented commands, targeting and selectors demo

```sh
make run
```

Run the following in a **second terminal**, except step 7, which runs inside a microterm pane.

1. **The tree.** `microterm ctl list` prints workspaces → windows → tabs → panes.
   `microterm ctl pane list --json | jq` shows id, tab, window, workspace, domain, title, cwd,
   process, size, focused, exited and exit_code. `microterm --help` lists `ctl` and
   no longer has the M9 flat command.
2. **Open a window and tabs.**
   ```sh
   eval "$(microterm ctl window new -- sh -c 'sleep 600')"; echo "window=$window tab=$tab pane=$pane"
   eval "$(microterm ctl tab new --window $window --title build-api -- sh -c 'sleep 600; true')"
   microterm ctl tab new --window $window --title build-web -- sh -c 'sleep 600'
   microterm ctl tab list --window $window
   ```
   A new window with three tabs appears.
3. **Selectors.** `microterm ctl tab list --match 'title:build*'` lists the two build tabs.
   `microterm ctl tab list --match '!title:build*'` lists the other one. A regex works too:
   `--match 'title:re:^build-(api|web)$'`.
4. **Ambiguity (exit 5).**
   `microterm ctl tab close --match 'title:build*'; echo $?` prints both candidates and `5`;
   nothing is closed. With `--all --force` both close.
5. **Close by id and by match, with and without `--force`.** Set `confirm_close = "always"` in
   the config (it hot-reloads), then:
   ```sh
   microterm ctl tab close --tab $tab; echo $?       # 8: confirm_close would ask; nothing closed
   microterm ctl tab close --tab $tab --force; echo $?   # 0: closed
   ```
   No dialog appears in either case. Set `confirm_close = "never"` and the first form works.
6. **Targets that do not exist.** `microterm ctl pane get --pane 999999; echo $?` is `3`.
   `microterm ctl pane close; echo $?` outside a pane is `1`: destructive verbs never fall back
   to the focused pane. `microterm ctl pane get` with no flags shows the focused pane.
7. **A pane addressing itself.** In a shell inside microterm:
   ```sh
   echo $MICROTERM_PANE $MICROTERM_TAB $MICROTERM_WINDOW
   microterm ctl pane get --json | jq .title     # this pane, with no flags
   microterm ctl tab close --force               # closes this very tab
   ```
8. **SSH panes get nothing.** In an SSH-domain tab, `env | grep MICROTERM` prints nothing: the
   local socket is not reachable from a remote host.
9. **Workspaces.** `microterm ctl workspace create tmp`, open a tab in it with
   `--workspace tmp`, switch back with `microterm ctl workspace switch default`, then
   `microterm ctl workspace delete tmp` removes it and its tabs. `delete default` and deleting the
   active workspace both fail with exit 1.
10. **JSON errors.** `microterm ctl pane close --match 'title:nope' --json` prints
    `{"error":{"code":"not_found",…}}` on stderr.
11. **Headless (tests).** `cargo test -p microterm --test ipc_e2e` drives every verb against
    `microterm --headless`.
12. **The shell.** `microterm sh` opens a prompt. Type `ta<TAB>` → `tab`, `tab cl<TAB> --pane <TAB>`
    lists live pane IDs with their titles, `pane list --match ti<TAB>` completes `title:`, and
    `workspace switch <TAB>` lists workspaces. `tab list`, `pane list --json` and friends behave
    like their `ctl` forms; `pane get --pane 99999` shows the prompt as `microterm [3]>`.
    `help pane` prints the pane verbs; Ctrl-D leaves. `echo 'list' | microterm sh` runs without a
    prompt.
