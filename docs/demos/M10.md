# M10 — SSH domains and reconnection demo

You need a host you can `ssh` to (a Linux or macOS machine, x86_64 or aarch64). For a quick local
try, enable Remote Login on a Mac, or run a throw-away sshd: `scripts/test-ssh.sh --local` prints
nothing but proves the same path in automated tests.

Until a release exists to download the daemon from, point microterm at a local build of it that
matches the *host's* platform:

```sh
cargo build -p mt_mux_server            # host == this machine
export MICROTERM_MUX_BINARY=$PWD/target/debug/microterm-mux
```

1. **Configure a domain** in `~/.config/microterm/microterm.toml`:
   ```toml
   [[ssh_domains]]
   name = "demo"
   host = "localhost"        # or your host / an ~/.ssh/config alias
   ```
2. **Open a tab.** `make run`, then `⌘⇧L` / `Ctrl+Shift+L` → *New tab in demo* (or run
   `microterm ssh demo`). The title bar shows `demo · connecting`. On first use confirm the host
   key (SHA256 fingerprint) with *Trust and connect*; enter a password/passphrase if asked. The
   daemon is installed under `~/.local/share/microterm/bin/` and the tab becomes a remote shell.
3. **Start something with a screen.** In the tab run `top` (or `vim`).
4. **Drop the network.** Easiest: in another terminal kill the TCP connection, e.g. on the
   client `sudo pfctl`/`ss -K` for the SSH connection, or disconnect Wi-Fi. The tab dims and shows
   *Connection to demo lost. Reconnecting in N s (attempt K).* Typing does nothing. The title bar
   dot turns amber.
5. **Watch it count.** The attempt number grows with backoff 1, 2, 4, 8, 16, 30 s. *Reconnect
   now* (or `Enter`) retries immediately.
6. **Restore the network.** The card disappears and the **same `top`** is back with its screen
   intact; typing works again.
7. **On the host**, `~/.local/share/microterm/bin/microterm-mux-0.1.0 list` shows the pane;
   `... kill PANE_ID` ends it.
8. **Failure cases.** Change the host key in `~/.ssh/known_hosts` (edit one character): connecting
   shows a *changed key* error with no way past it. Close the tab from the card with *Close tab*
   while disconnected: the remote process keeps running (see `list`).
9. **Fallback.** Set `multiplexing = "none"` on the domain, or point `MICROTERM_MUX_BINARY` at a
   non-file: the tab shows a notice and works as a plain session (it will not survive a drop).

Automated: `make test-ssh` (Docker) or `scripts/test-ssh.sh --local` (throw-away sshd) runs auth,
host-key, bootstrap and kill-the-connection-then-reconnect tests against a real server.
