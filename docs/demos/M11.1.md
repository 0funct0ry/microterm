# M11.1 — Custom context menus demo

```sh
make run
```

1. **Panes group on the clicked pane.** Press `⌘D` (Linux `Ctrl+Shift+D`) so the tab has two
   panes; focus is on the right one. Right-click the **left** pane: focus stays on the right
   pane, and the menu shows Copy … Clear scrollback, then a **Panes** heading with Toggle zoom,
   Swap ▸, Rotate, Split left/right/up/down and Close pane, with key chips. Choose
   **Split left**: a new shell appears left of the pane you clicked and takes focus. Right-click
   again and try **Swap ▸ Swap right**, **Rotate** and **Toggle zoom**; each acts on the clicked
   pane.
2. **Keyboard.** Add to `~/.config/microterm/microterm.toml` (it reloads live):
   ```toml
   [[keys]]
   key = "cmd+shift+m"            # Linux: "ctrl+shift+m"
   action = { ShowContextMenu = "viewport" }
   ```
   Press it: the menu opens at the cursor. Use ↓/↑, → into Swap and ← back, type `spl up` to
   filter to "Split up", press Enter. Esc closes (the first Esc clears a filter).
3. **A spawn item with the selection.** Add:
   ```toml
   [[context_menu.viewport.items]]
   id = "echo"
   label = "Echo {selection}"
   when = "selection"
   confirm = "auto"
   spawn = { command = ["sh", "-c", "printf 'arg=[%s]\nenv=[%s]\n' \"$1\" \"$MT_SELECTION\"; env | grep ^MT_; exec sh", "sh", "{selection}"], where = "split-right" }
   ```
   Run `echo 'a; rm -rf ~ $(id)'`, select the text `a; rm -rf ~ $(id)` with the mouse and
   right-click it. "Echo a; rm -rf ~ $(id)" is in the menu; choosing it shows the confirmation
   dialog with the exact command (it uses terminal text, and `rm -rf` matches
   `[menu_security] dangerous`). Run it: a split opens to the right printing the selection once
   as a single argument and once from `MT_SELECTION`, plus the other `MT_*` variables. Without a
   selection the item is hidden.
4. **A tab menu item.** Add:
   ```toml
   [[context_menu.tab.items]]
   label = "Duplicate tab"
   spawn = { command = ["sh"], cwd = "{cwd}", where = "tab" }
   ```
   Right-click a tab: "Duplicate tab" appears after Close tab / Close other tabs / Rename….
5. **Mistakes keep the old menus.** Change `context_menu.tab` to `context_menu.tabb`, or put
   `{selection}` in the tab item's label, and save. The banner shows
   `microterm.toml:L:C — context_menu.tabb: unknown menu "tabb" (did you mean "tab"?) …` (or
   `placeholder {selection} is not available in menu "tab"; available: …`), and the menus keep
   working as before. Fix it and the banner clears.
6. **Headless and scripted.** In another terminal:
   ```sh
   microterm --headless &           # prints its socket path
   export MICROTERM_UNIX_SOCKET=<that path>
   microterm ctl tab new -- sh       # note the pane id, e.g. 1
   microterm ctl pane split --pane 1 --direction left
   microterm ctl menu list
   microterm ctl menu show viewport --pane 1
   microterm ctl menu invoke viewport/zoom --pane 1
   microterm ctl pane get --pane 1 --json | jq .zoomed     # true
   microterm ctl menu invoke viewport/close_pane --pane 1 --dry-run
   microterm ctl menu check
   ```
   `menu invoke` without `--pane` exits 1; an unknown item exits 3; an item with `confirm = true`
   exits 8 until you add `--force`. `microterm ctl events --type menu.invoked` prints one line per
   `send`/`spawn`/`ctl` item that runs.
7. **Palette.** Items with an `id` appear in the command palette as "Viewport menu: Echo …", and
   `action = { InvokeMenuItem = "viewport/zoom" }` binds any item to a key.
