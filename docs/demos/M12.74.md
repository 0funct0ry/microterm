# M12.74 — Pane-scoped key bindings and palette entries demo

```sh
make run
```

Set `[private_osc]` / `enabled = true` in `microterm.toml` first. The steps are scripted in
`scripts/private_osc/pane_keys` (also run by `all`).

1. **Binding.** Split the tab into two panes. In pane 1 run `mt-key add --id t ctrl+alt+t -- echo tested`.
   Press `Ctrl+Alt+T` in pane 1: `echo tested` runs there.
2. **Pane only.** Focus pane 2 and press `Ctrl+Alt+T`: nothing is typed.
3. **Reserved and bound chords.** `mt-key add --id q cmd+q -- exit` (Linux: `ctrl+shift+q`) registers nothing.
   Bind `ctrl+alt+t` yourself in `[[keys]]`, then register it from a pane: refused. Run
   `microterm ctl private-osc status` and see the malformed counter grow.
4. **Palette.** In pane 1 run `mt-palette add "Run tests" -- echo tested`. Open the command palette: a
   `Run tests` row with the chip `pane` is at the top. Focus pane 2 and open it again: it is gone.
5. **Live update.** With the palette open in pane 1, run `mt-palette clear` from another place that can
   write to pane 1: the row disappears.
6. **Safety.** `mt-key add --id d ctrl+alt+d -- rm -rf /` asks for confirmation when pressed. In `--ctl`
   mode, `mt-key add --ctl --id c ctrl+alt+c -- pane notify --pane 2` is refused.
7. **SSH.** In an SSH pane both are ignored until `[menu_security] allow_remote_items = true`; even then
   `spawn` does not exist. After a reconnect they are restored by the daemon replay.
8. **Master switch / gates.** Toggle private OSC (or set `key = false` / `palette = false`): both vanish
   and do not return. Exiting the shell or `reset` also removes them.
