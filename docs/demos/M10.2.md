# M10.2 — ctl: run, wait and last-command output demo

```sh
make run
```

Run the following in a **second terminal**, except steps 5 and 6, which use a microterm pane.

1. **Run a command and read its result.**
   ```sh
   microterm ctl pane run --json -- sh -c 'echo built; exit 3'
   ```
   prints `{"pane":…,"tab":…,"exit_code":3,"signal":null,"duration_ms":…,"output":"built\n","truncated":false}`
   and `ctl` exits `0`. A tab opens, runs, and closes. `echo $?` after a plain
   `microterm ctl pane run --propagate-exit -- sh -c 'exit 42'` prints `42`; `exit 3` prints `1`.
2. **Dev server pattern.**
   ```sh
   microterm ctl pane run --detach --title dev -- sh -c 'sleep 2; echo ready on 3000; sleep 600'
   microterm ctl pane wait --match title:dev --match 'ready on (\d+)' --timeout 120s --json
   ```
   The second command returns after about two seconds with `"reason":"match"` and `3000` in
   `match.groups`. `--match title:dev` chose the pane, the other `--match` is the regex.
3. **Timeouts never kill.**
   ```sh
   microterm ctl pane wait --match title:dev --match 'never appears' --timeout 500ms; echo $?   # 6
   microterm ctl pane run --timeout 1s -- sh -c 'echo hi; sleep 30'; echo $?                    # hi, then 6
   ```
   The `sleep 30` tab is still open.
4. **Keep an exited pane.**
   ```sh
   microterm ctl pane run --keep -- sh -c 'echo done; exit 2'
   microterm ctl pane list --match 'exited:true' --json
   ```
   The tab stays and shows `[process exited with status 2]`; the pane lists as `exited: true`
   with `exit_code: 2`. Close it with `microterm ctl pane close --match exited:true --force`.
5. **Shell integration.** In a zsh (or bash, or fish) tab inside microterm:
   ```sh
   eval "$(microterm shell-integration zsh)"
   ```
   Run `ls` and `false`. Copy mode (`[` / `]`) now jumps between prompts.
6. **Last command.** From the second terminal, with `$MICROTERM_PANE` of that tab as `$pane`:
   ```sh
   microterm ctl pane get-text --pane $pane --last-command --json
   ```
   returns `{"command":"false","exit_code":1,"cwd":"…","text":"","finished_at":"…Z"}`. With
   `--last-command 2` it is the `ls` listing. In a pane without the snippet it exits `7`.
7. **Run in an existing shell.**
   ```sh
   microterm ctl pane run --in $pane --json -- echo hello
   ```
   returns `{"pane":…,"exit_code":0,"output":"hello\n","truncated":false}`: no prompt, no echoed
   command line. While a command runs in that tab (`sleep 30`), the same call exits `9` and types
   nothing. `--timeout 1s` on a long command exits `6` and the command keeps running.
8. **Wait for a command.**
   ```sh
   microterm ctl pane send-text --pane $pane --no-paste $'sleep 3\r'
   microterm ctl pane wait --pane $pane --command-finished --json
   ```
   returns `"reason":"command_finished"` after three seconds. `--idle 2s` and `--exit` work the
   same way.
9. **Disconnecting.** Start `microterm ctl pane run --in $pane -- 'sleep 5; echo b'` and press
   Ctrl-C. The wait stops, the shell finishes the command anyway, and
   `microterm ctl pane get-text --pane $pane --last-command` shows `b`.
10. **The output cap.** Set `[ctl] capture_max_bytes = 100` in the config (it hot-reloads) and run
    `microterm ctl pane run --json -- seq 1 500`: `output` is the last 100 bytes and `truncated`
    is `true`.
11. **Over SSH.** In an SSH-domain tab with the snippet loaded on the remote shell, run a
    command, drop the connection and let it reconnect (see the M10 demo): afterwards
    `microterm ctl pane get-text --pane $pane --last-command` still returns that command, because
    the daemon's replay carries the marks.
12. **Headless (tests).** `cargo test -p microterm --test ipc_e2e` drives every exit code against
    `microterm --headless`; `cargo test -p mt_term replay` covers the replay round trip with marks.
