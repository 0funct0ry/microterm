# M12.6 — Triggers demo

```sh
make run
```

1. **Off by default.** With a stock config the **View** menu has no *Triggers* row, the palette
   has no "trigger" or "marker" rows, and the pane context menu has no *Create trigger from
   selection…*. Run **Toggle triggers panel** from the palette: a toast says "Triggers are
   disabled — set `triggers.enabled = true`" with an **Open config** button. `microterm ctl
   trigger list` exits 10. `~/.config/microterm/triggers.toml` does not exist.
2. **Turn it on.** Put `[triggers]` / `enabled = true` in `microterm.toml` and save: the rows
   appear without a restart.
3. **Create from a selection.** Run `echo 'error: build failed'`, select that output line, then
   **Edit ▸ Create Trigger from Selection…** (or the context menu). The panel opens with the
   regex `error: build failed` and a `highlight` action. Name it *Build failed*, **Add action ▸
   tab_color** (set `red`), **notify**, **findings**, and **Save**.
3b. **Typing does not fire rules.** With shell integration on, type `echo 'error: build failed'`
   without pressing Enter (also with a dimmed autosuggestion): nothing is underlined and the
   counter does not move. After Enter only the printed line matches. Set `scope = "any"` on the
   rule (or the editor's *Match in* ▸ *every line*) and the typed line matches too.
4. **Watch it fire.** Run `echo 'error: build failed'` again: the line is highlighted, the tab
   turns red (hover it: "Color: red (trigger: Build failed)"), a notification with the tab badge
   appears, and *Findings* has a row. Run `seq 1 300`, then click the finding: the pane scrolls
   back to the line and it flashes for 600 ms. Bind `NextMarker` and `PreviousMarker` in `[[keys]]`
   (or use the palette) and step through the markers; each finding left a tick on the scrollbar.
5. **Test is a dry run.** Open the rule, click **Test**: it lists what *would* run with the text
   expanded, and nothing happens (no highlight, no notification, no file).
6. **An event rule.** New trigger → **Event**, `command_finished`, exit `failure`, applies to
   `!focused:true`, action `notify` with message `{title} exited with {exit}`. With shell
   integration on, start `sleep 1; false` in one tab and switch to another: a notification
   arrives when it fails.
7. **A prompt without a newline.** Rule regex `Continue\? \[y/N\]`, action `bell` or `notify`.
   Run `printf 'Continue? [y/N] '; sleep 5`: it fires about 250 ms after the prompt appears.
8. **Hostile output.** Rule `error: x`, action `counter` and `highlight`, cooldown 0. Run
   `yes 'error: x' | head -100000`: the UI stays responsive, the row shows *suppressed* and the
   footer shows the lines dropped; `ctl trigger list` shows both.
9. **The second gates.** Add a `clipboard`, a `snapshot` and a `screenshot` action to a rule: they
   are greyed with "Set `triggers.allow_…` = true in microterm.toml" and do nothing when the rule
   fires (the row's dot says why). Set `allow_clipboard = true` and `allow_capture = true` and
   save the config: now a firing copies the match (with a toast "Trigger … copied N characters to
   the clipboard") and writes `~/.local/share/microterm/captures/<rule>-<date>-<time>-<n>.txt|png`
   with mode `0600` in a `0700` directory. A line containing `password=hunter2` is stored as
   `password=‹redacted›`.
10. **ctl.** `microterm ctl trigger list`, `get ID`, `disable ID` (the file is unchanged),
    `pause`, `resume`, `test ID --in $MICROTERM_PANE`. `microterm ctl trigger new` is not a
    command, and there is no MCP tool for triggers.
11. **SSH and reconnect.** In an SSH pane the same rule fires. Drop the connection and let it
    reconnect: old matches do not fire again.
12. **Turn it off.** Set `enabled = false`: highlights, markers, the red tab, counters and
    trigger titles vanish, a recording started by a rule is stopped and saved ("Recording
    stopped: triggers disabled"), and the files in the captures directory stay.
13. **Bench.** `make bench` runs `bench/triggers.sh`: the worker scans at least 200 000 lines/s
    with 8 rules and `cat` of 100 MB with the line tap and 8 rules stays within 10 % of the run
    without.
